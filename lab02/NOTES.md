
## Понимание состояний Git 

## Рабочая папка (Working Directory)
Это папка `lab02` на моём диске, где я пишу и меняю файлы (например, `main.cpp`).  
Пока я правлю код в редакторе, Git видит эти изменения как «модифицированные», но они ещё не зафиксированы. Это моё рабочее пространство: здесь можно экспериментировать, запускать тесты, собирать проект через g++/CMake.

## Индекс (Staging Area)
Это «зона подготовки» к коммиту. Когда я делаю `git add lab02/NOTES.md`, я говорю Git: «Этот файл хочу включить в следующий коммит».  
Индекс удобен тем, что можно собрать коммит из нескольких файлов: например, добавить только документацию и один исправленный `.cpp`, а остальные правки оставить на потом.

## Коммит (Commit)
Это снимок состояния проекта на конкретный момент. После `git commit -m "Describe local Git states"` Git сохраняет версию файлов из индекса как отдельный шаг в истории.  
Теперь у меня есть точка, к которой можно вернуться, если что-то сломается в коде. Для лабораторной это важно: можно фиксировать этапы реализации (например, «добавил ввод данных», «реализовал поиск»).

## Различия Git и GitHub
Git - это система контроля версий,которая хранит снимки состояния всех файлов проекта в каждый момент фиксации (коммита). При этом, если файл не менялся, Git не дублирует его, а ссылается на предыдущий идентичный снимок.
Такой подход позволяет эффективно отслеживать всю историю и мгновенно переключаться между версиями. 
Git-репозитории можно разместить на платформе GitHub.

GitHub - веб-служба для хранения Git-репозиториев и совместной работы над проектами. Она полезна и для личных пректов, поскольку функции решения позволяют структурировать историю
изменений и поддерживать порядок в репозиториях.

## Использованные команды
git status - состояние проекта, измененные и не добавленные файлы, индексированные файлы.Она выводит информацию обо всех изменениях, внесенных в дерево директорий проекта по сравнению с последним коммитом рабочей ветки;
отдельно выводятся внесенные в индекс и неиндексированные файлы.

git diff - определяет изменения между объектами в проекте - деревьями (файлов и директорий).

git diff --staged сравнивает индекс (подготовленные изменения) и последний коммит. Показывает  всё, что Git зафиксирует при следующем git commit


## Ветки (Branches)

**Что такое ветка?**  
Ветка — это указатель на конкретный коммит. Ветка `main` — это просто метка, которая показывает «текущее стабильное состояние проекта». Когда мы создаём новую ветку (например, `explain-branches`), мы делаем ещё одну такую метку, которая сначала указывает на тот же коммит, что и `main`.

**Что происходит с веткой при новом коммите?**  
Когда ты делаешь коммит в какой‑то ветке, Git:
1. Создаёт новый коммит с твоими изменениями.
2. Передвигает указатель ветки на этот новый коммит.  
При этом другие ветки не двигаются. Поэтому в ветке `explain-branches` появляются новые изменения, а в `main` их пока нет.

**Что делает слияние (merge)?**  
Слияние — это создание нового коммита, который объединяет две ветки. Команда `git merge` берёт изменения из одной ветки и «накладывает» их на текущую.  
Флаг `--no-ff` заставляет Git создать отдельный коммит слияния, даже если технически можно было бы просто передвинуть указатель. Это полезно для истории: сразу видно, когда и что именно слили.**Что такое ветка?**
